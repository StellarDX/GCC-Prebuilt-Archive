# GCC 预编译工具链（存档）

基于官方GCC源码预编译的GCC工具链

**免责声明：预编译包依赖宿主系统的glibc版本，且不同系统的ABI可能不一样，因此此处不保证这些包能在所有环境下正常运行**

## 项目背景

C/C++语言标准是会持续更新的，从C++11/14/17/20/23，到现在C++26已经出了，GCC也在跟进。但是一些Linux尤其是部分国产操作系统（如麒麟、统信UOS、Deepin等）由于系统更新策略、稳定性考量或维护周期限制，官方软件仓库中的GCC版本往往滞后于上游多年，如Deepin官方源才更到GCC-13，实测现在13也装不上了,只能用12。

结果就是一些要用新特性的项目/开发者（比如我）会遇到很棘手的问题：

 - 无法使用C++23/26等现代语法特性，阻碍代码现代化
 - 缺少最新的编译优化技术，影响性能
 - 与上游项目依赖的最低编译器版本不兼容，导致一系列问题
 - 安全漏洞修复补丁无法及时同步

所以我就开了个仓库填补这一空白，用来存放预编译的新版本GCC二进制工具链。

---

## 构建特性

全量编译库文件和相关编译器，分default包和单语言分包：

| 包类型 | LTO（链接时代码优化） | 适用场景 |
|--------|----------------------|----------|
| **Default包** | 启用LTO | 语言选项为default（含C，C++，Fortran和ObjC），常用语言一次到位 |
| **单语言包** | **关闭LTO** | 只需要单个语言（追求整洁可选） |

> 注：LTO存在的意义在于打破编译单元的物理隔离，但是需要的资源超级多且会拖慢编译，还可能会因跨编译单元的优化引入难以追踪的运行时问题。因此大多数项目都用不到它，至少我没见过几个用到它的项目。

## 使用说明

### 安装方式

1. 解压到指定目录
2. 配置环境变量（就是添加到PATH，可选，一般IDE都可以自己指定编译器路径，我之前用过的VSCodium/VSCode和QtCreator都可以）

### 验证安装
```bash
/path/to/gcc --version
/path/to/g++ --version
```
